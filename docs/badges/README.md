## 1. 운영자가 원하는 것 (그대로 옮김)

운영자 말(2026-11-14, 마지막 정리):
> 내가 예시로 올려준 월계관의 왕관 돌아가는 GIF 에서 **가운데에 있는 부분은 등급 표시로 씨앗부터 쭉 올라가는 그 색깔**로 가져가고, **1등만 금색 월계관에 왕관**을 쓰는데 **왕관만 360도로 계속 돌아가는 형태**였으면 좋겠다. **큰 나무랑 생명의 나무가 조금 더 특별**했으면 좋겠어서 등급표 자체가 **반짝반짝 빛났으면** 좋겠다. 큰 나무는 **밑의 등급(열매)과 색 차이가 많이 안 나고**, 더 상위 등급이란 느낌이 안 나서 **더 골드 계열**의 색이 들어갔으면 좋겠다.

풀어 쓰면:

1. **메달 가운데 = 등급 색.** 7등급 '겨자씨의 성장' — 색은 운영자가 정한 순서 그대로:

   | 단계 | 이름 | 색 |
   |---|---|---|
   | 1 | 겨자씨 | 회색 |
   | 2 | 새싹 | 초록 |
   | 3 | 줄기 | 파랑 |
   | 4 | 꽃 | 빨강 |
   | 5 | 열매 | 노랑 |
   | 6 | 큰 나무 | **금색(진한 금속 광택의 골드)** |
   | 7 | 생명의 나무 | 무지개(유일) |

   - 운영자가 싫어한 것: "노랑인지 빨강인지 애매하게 표현되는 색" → 등급끼리 **한눈에 구분**돼야 한다.
   - **열매(노랑)와 큰 나무(금)** 가 가장 헷갈린다. 큰 나무는 갈색 기운 없이 밝고 깊은 금, 금속 광택, 열매보다 확실히 '더 높은 등급'으로 보여야 한다.
   - 색을 바꾸는 방식은 **메달 자체의 색**이다. '테두리 색만 바꾸기'는 운영자가 거절했다.
2. **큰 나무·생명의 나무는 특별하게**: 메달(등급표) 자체가 반짝반짝 빛난다(빛줄기가 지나감, 별빛 반짝임, 빛 번짐 등). 1~5등급은 가만히 있어도 된다.
3. **1등(그 활동에서 가장 많이 한 교우)만** 금색 월계관 + 왕관. 이것이 '1등'이라는 유일한 표시다. 색은 계속 등급을 뜻한다 (**색 = 등급, 금 월계관 + 왕관 = 1등**).
4. **왕관만 360도, 시계 방향으로, 계속 돈다.** 납작한 그림이 좌우로 뒤집히는 것이 아니라 예시 GIF 처럼 **입체(3D)로** 돈다. 월계관·메달은 돌지 않는다.
5. 왕관은 **크게, 눈에 확 보이게**, 빛·음영이 들어간 **진짜 금**처럼. 예시처럼 붉은 보석(루비), 반짝임.
6. 예시 그림의 구성: 금빛 번짐(후광) 위에 — 뾰족한 잎이 풍성한 금 월계관(아래에서 만나고 위는 열림, 맨 아래 다이아몬드) — 가운데 둥근 메달(두꺼운 금 테 + 안쪽 판 + 돋을새김 문양) — 메달 위에 얹힌 왕관 — 둘레의 반짝이는 별.

### 내가(앞 세션) 잘못 이해했던 것 — 되풀이하지 말 것
- 등급 메달을 '보석 재질(에메랄드·사파이어…) + 은 테두리'로 바꾼 시안(`trial-3d-tiers.png`)을 냈는데 **요청한 적 없는 변경**이다. 운영자가 바란 것은 위 표의 색을 3D 품질로 살리는 것이지 재질·테두리 체계를 바꾸는 것이 아니다. 버린다.
- 1등 배지 안쪽을 남색 한 가지로 통일한 적이 있는데 거절당했다("등급이 들어가야지").

`3d-pipeline/` 쓰는 법(참고용, 그대로 쓸 의무는 없다):

- 크로미움은 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader` 로 WebGL 이 된다. 512px 24장에 1~2분.
- 배운 것: 금은 **주변 환경(반사되는 것)** 이 품질을 정한다. 흰 방(RoomEnvironment)은 금이 허옇게, 어두운 방은 갈색으로 나온다 → 따뜻한 중간 밝기 방 + 밝은 조명판 몇 개. 투명 배경에서는 블룸 패스가 알파를 잃으므로 빛 번짐은 뒤에서(파이썬) 얹었다.

품질을 예시만큼 올릴 방법은 제작 세션이 판단한다. 후보:
- 3D 를 더 다듬기(잎을 더 크고 풍성하게 겹치기, 메달 테를 두껍게, 금 재질·조명, 빛 번짐과 별을 예시만큼 세게, 왕관 모양을 예시처럼).
- **예시 GIF 의 낱장을 바탕으로 쓰기**: 월계관·왕관·빛은 예시 그대로 두고 가운데 메달 판만 등급 색으로 바꾸기(운영자가 준 그림이므로 써도 된다. 357px·12장이라 크게 볼 때 화질, 등급별 색 입히기가 과제).
- 둘을 섞기(왕관·월계관은 한 벌만 만들고, 가운데 메달만 등급/문양별로).

## 3. 앱에 넣을 때 지켜야 할 것

- **쓰이는 곳과 크기**: 이름 옆(18px 안팎, 대표 배지 1개) · 배지 목록/수집 화면(40~64px) · 자세히 보기(크게, 200px 안팎). 작은 크기에서도 등급 색과 '1등'(왕관)이 구분돼야 한다. 이름 옆처럼 아주 작고 많이 뜨는 곳은 **멈춘 그림**이 낫다(움직이는 그림 수십 개가 한 화면에 뜨면 폰이 느려짐).
- **밝은 화면·어두운 화면 둘 다**에서 보기 좋아야 한다 → 배경이 투명해야 하고, 빛 번짐이 밝은 바탕에서 지저분하지 않은지 확인(예시는 검은 바탕 기준).
- **파일 무게**: 조합이 많다. 등급 7 × 활동 사다리 6 + 1등(문양 33가지 × 등급 7). 조합마다 움직이는 그림을 만들면 너무 무겁다 → **겹쳐 쓰기**를 권한다: (가) 가운데 메달: 등급 7장(문양 없이) + 문양은 지금처럼 SVG 로 얹기 또는 등급×문양 멈춘 그림, (나) 월계관+빛: 1장, (다) 도는 왕관: 움직이는 webp/APNG 1개를 모두가 같이 씀. 숫자 판(30, 100, 2,500 …)은 글자라 코드로 얹는다.
- `prefers-reduced-motion` 이면 멈춘 그림.
- 접근성 글(`aria-label`: '소통왕 (큰 나무) 1등')은 지금처럼 유지.
- 코드 자리: `components/BadgeIcon.tsx` (`TierMedal`·`ChampionMedal`·`BadgeIcon({badge,size,className,champion,tier})`), 등급·사다리 `lib/badges.ts` (`TIERS`·`LADDERS`·`shownBadges`·`tierNum`), 쓰는 곳 `components/MemberBadges.tsx`·`components/BadgeCollection.tsx`. 그림 파일은 `public/badges/` 아래에 두면 된다.
- `svg-wip.patch`: 앞 세션이 올리지 않은 SVG 작업(왕관·월계관 다시 그림, 큰 나무 색 `['#fff6c8','#f0b92a','#a87200']`, 큰 나무·생명의 나무 반짝임 CSS, 등급을 아는 1등 배지를 `TierMedal` 로 그리기). 3D 그림으로 가면 대부분 필요 없지만 **'1등 배지에 그 교우의 등급 색 입히기'(`BadgeIcon` 의 `tier` 인자)** 와 작은 크기용 대체 그림으로 쓸 수 있다. `git apply docs/badges/svg-wip.patch`.

## 4. 함께 정해진 것: 1안 — 등급 없는 1등 배지 27개에도 7단계 (운영자 승인: "1안으로 준비해줘")

지금 7단계 사다리는 6가지(댓글·공감·글·출석·연속·기도)뿐이라, 나머지 1등 배지(사진작가 등 27개)는 '등급 색'을 입힐 등급이 없다. 운영자가 1안(모두 7단계를 만든다)을 골랐다. 아래 숫자표는 **보여 드렸고 아직 '올려 줘'는 받지 못한 초안**이다.

  2. `ex2/`: `example-crown.gif` 를 `f00.png~f11.png` 로 풀고, 문양 `emb/<키>.png`(1024px, `EMBLEMS` 를 흰색 SVG 로 뽑아 투명 배경으로 찍음 — `EMBLEMS` 를 잠깐 export)
  3. `python3 assets.py out <키,키,…>` → `out/` 을 `public/badges/3d/` 로. 시안 그림은 `python3 make2.py all`
  - `make.py`: 가운데 판(`disc`)·등급 메달(`tier_frames`)·검은 바탕→투명(`to_rgba`) / `make2.py`: 왕관 지운 바탕(`base_plate`)·월계관 금빛 본뜨기(`laurel_look`)·왕관 색 입히기(`crown_frames`)·1등 합치기(`champ_frames`)
- **1안(27가지 7단계)** 도 넣음: `lib/badges.ts` `LADDERS` 33줄, SQL `supabase/badge-ladders-27.sql`(숫자 넣고 그 자리에서 조용히 계산 — 알림 없음), `member-badges.sql` 에도 같은 숫자. 사다리 id 에는 밑줄 금지(SQL 이 `t_<id>_<단계>` 를 밑줄로 가름: `toppost`·`commentloved`)
- 버린 것: three.js 로 통째로 만든 시안(`trial-3d-champions.png`)과 그 도구, 재질로 바꾼 등급표
- 한계: 예시 GIF 가 358px 라 1등 틀은 아주 크게 보면 부드럽다. 운영자에게 원본(큰 그림·영상)이 있으면 `f*.png` 만 바꿔 다시 만들면 됨
